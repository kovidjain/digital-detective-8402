# Mission 6 — Git and GitHub

## Mission title

Git and GitHub.

## Task / objective

I needed to explain how Git records changes locally and how GitHub supports sharing, review, and collaboration. I also needed to describe commits, branches, and pull requests in a practical workflow.

## Work completed

- Explained the difference between a working tree, staging area, and commit history.
- Described branches as separate lines of development.
- Explained how a pull request supports review before changes reach a shared branch.
- Documented a small collaboration workflow using Git and GitHub.
- Kept examples general and left out private account, device, and network information.

## Commands / tools used

- `git status` — checked changed and staged files.
- `git add` — selected changes for the next commit.
- `git commit` — recorded a local snapshot with a message.
- `git log` — inspected commit history.
- `git branch` — listed or created branches.
- `git push` — sent commits to a remote repository.
- GitHub — hosted the repository and pull-request review.

## My understanding

Git is the version-control system that records snapshots in a local repository. GitHub is a hosted service that stores repositories and adds collaboration features such as pull requests, discussions, and review. A branch lets work progress separately, while a pull request gives people a place to compare and discuss the proposed changes before merging.

## Difficulties faced

It was easy to mix up Git and GitHub because their names are similar. The staging area also needed careful explanation because adding a file does not create a commit by itself.

## How I resolved them

I described the workflow in order: inspect changes, stage selected files, commit locally, push to a remote, and open a pull request for review. I kept the local commands separate from the GitHub collaboration steps.
